# پیاده سازی DBR

سامانه فارسی مدیریت تداوم کسب‌وکار با React، TypeScript، Vite و IndexedDB. این نسخه نخست، شامل داشبورد تعاملی، ثبت و ویرایش رکوردهای ماژول‌ها، کاتالوگ مرجع DBR، گزارش و پشتیبان‌گیری است.

## اجرای مستقیم برای کاربران ویندوز

نسخه ZIP اصلاح‌شده را دریافت کنید و با **Extract All** کاملاً از حالت فشرده خارج کنید. سپس فایل **index.html در ریشه پوشه DBR-Website** را با Edge یا Chrome باز کنید. این فایل، نسخه کامل تک‌فایلی است و به نصب Node.js، اینترنت یا اجرای سرور نیاز ندارد. همچنین می‌توانید فایل `DBR-Standalone.html` را مستقیم از GitHub دریافت و باز کنید.

مرورگر مدیریت‌شده محیط Codex بازکردن URLهای `file://` را با سیاست مدیریتی مسدود می‌کند؛ بنابراین آزمون خودکار از محتوای دقیق HTML استخراج‌شده، روی مسیر محلی مجاز استفاده می‌کند. آزمون بازکردن مستقیم file:// در این محیط انجام نشده است.

نسخه قدیمی ZIP، فایل توسعه را در ریشه قرار می‌داد و با دوبارکلیک صفحه خالی نشان می‌داد. در نسخه اصلاح‌شده، فایل‌های توسعه در پوشه `source` قرار دارند. `source/index.html` فقط از طریق Vite اجرا می‌شود. نسخه عادی `dist/index.html` نیز باید از طریق HTTP سرو شود.

تمام کد، فونت، کاتالوگ مرجع و کتابخانه‌های خروجی در HTML مستقل تعبیه شده‌اند. در حالت `file://` نیازی به Service Worker نیست و نصب PWA فعال نمی‌شود. ذخیره IndexedDB به مرورگر و محل فایل وابسته است؛ پیش از جابه‌جایی فایل یا مرورگر، از اطلاعات پشتیبان JSON بگیرید.

برای بازتولید بسته:

```bash
npm run build
npm run package
```

آزمون `e2e/portable.spec.ts`، ZIP واقعی را در مسیری دارای فاصله و حروف فارسی استخراج می‌کند، محتوای کامل index را بدون فایل جانبی و با شبکه قطع اجرا می‌کند و ثبت اطلاعات، ماندگاری، کاتالوگ، پشتیبان، بازیابی، Word و Excel را بررسی می‌کند.

## راه‌اندازی توسعه

Node.js 24 و npm. در همین checkout کار کنید؛ محیط ایزوله است و نیازی به worktree نیست.

```bash
cd /workspace/BCMS
npm ci --cache /workspace/.npm
npm run dev -- --port 5173
```

ساخت، آزمون و اجرای نسخه تولید:

```bash
npm run build
npm test
npx playwright test
npm run preview -- --port 4173
```

Playwright از Chromium موجود در `/usr/bin/chromium` استفاده می‌کند. نصب مرورگر اضافی لازم نیست.

## استفاده

- در آغاز، سازمان و رکوردهای **نمونه** نمایش داده می‌شوند؛ هیچ امتیاز نمایشی، ارزیابی واقعی نیست.
- از «سازمان و دامنه BCMS» نام سازمان را ذخیره کنید یا پس از پشتیبان‌گیری، سازمان خالی بسازید.
- فرم‌های هر ماژول برای ثبت، ویرایش، وضعیت، مالک، پیشرفت، موعد و شواهد در دسترس است. حذف تأیید می‌خواهد.
- در اهداف بازیابی، RTO، RPO، MTPD و زمان آزمون را ثبت کنید. در ارزیابی ریسک، احتمال و پیامد را وارد کنید.
- در رادار DBR، دامنه و الگو را مرور و ارزیابی‌های سازمان را ثبت کنید. رادار از امتیازهای ذخیره‌شده ساخته می‌شود.
- Excel و Word از مرکز گزارش دانلود می‌شوند. PDF از پنجره چاپ مرورگر با انتخاب Save as PDF تهیه می‌شود.
- JSON اطلاعات کامل پشتیبانی‌شده را منتقل می‌کند. هنگام ورود، پیش‌نمایش، اعتبارسنجی و انتخاب ادغام یا جایگزینی وجود دارد. ادغام، رکورد موجود با شناسه تکراری را حفظ می‌کند.
- برای چند سازمان، پشتیبان جداگانه نگه دارید. این نسخه یک سازمان فعال دارد.
- پوسته تاریک در تنظیمات یا بالای صفحه فعال می‌شود و بین نشست‌ها حفظ می‌شود.

## ذخیره‌سازی و آفلاین

پایگاه IndexedDB با Dexie دارای نسخه ۱ و جدول state است. schemaVersion پشتیبان `1.0.0` است. نسخه ناسازگار رد می‌شود؛ مهاجرت به نسخه‌های بعدی هنوز لازم نشده است. هر ذخیره، یک عملیات اتمی روی state است. پشتیبان JSON رمزنگاری ندارد. داده‌ها به مرورگر، پروفایل و origin وابسته‌اند؛ همگام‌سازی یا احراز هویت سازمانی وجود ندارد.

ساخت تولید، service worker را با فهرست کامل فایل‌ها تولید می‌کند. پس از اولین بارگذاری کامل روی HTTPS یا localhost، کار آفلاین ممکن است. سرور توسعه برای آزمون آفلاین مناسب نیست. از Clear Site Data بدون پشتیبان استفاده نکنید.

## روش محاسبه

- پیشرفت کلی: میانگین ساده پیشرفت رکوردهای ثبت‌شده؛ شاخص داخلی نرم‌افزار است و معادل درصد انطباق ISO نیست.
- بلوغ: میانگین امتیازهای ارزیابی DBR (۰ تا ۵). صفر بدون ارزیابی، به معنی نبود داده است.
- رادار: میانگین ارزیابی هر دامنه یا آخرین ارزیابی آن. خط هدف ثابت ۴ از ۵، صرفاً هدف نمایشی است.
- شکاف بازیابی: زمان آزمون منهای RTO؛ مقدار مثبت نشان‌دهنده تأخیر است. RTO باید کمتر از MTPD باشد.
- ریسک: احتمال × پیامد، هرکدام ۱ تا ۵. امتیاز ۱۵ به بالا زیاد محسوب می‌شود؛ روش محصول است، الزام ISO نیست.
- پوشش آزمون: نسبت آزمون‌های تکمیل‌شده به کل آزمون‌ها؛ تضمین عملی آمادگی نیست.

## منشأ مرجع و محدودیت‌ها

`public/atlas.json` از فایل ارسالی `DBR_Continuity_Capability_Atlas_v0.3.2_HOT_FA.html` استخراج شده است: ۱۲ دامنه و ۴۰ الگوی نامزد. محتوای مرجع به صورت متن امن React نمایش داده می‌شود؛ HTML آن اجرا نمی‌شود. وضعیت پژوهشی الگوها با بلوغ سازمان متفاوت است. کاتالوگ ۱۶ دامنه‌ای و متن استانداردهای ISO ارائه نشده‌اند؛ نگاشت معتبر بندهای ISO یا ادعای گواهی ایجاد نشده است.

فونت محلی Yekan از بسته `typeface-yekan@1.0.11` (نسخه ParsMizban، OFL) است؛ مجوز در assets موجود است. نشان SVG از روی تصویر ارسالی بازطراحی شده است؛ فایل اصلی لوگو در فایل‌های قابل‌دانلود موجود نبود و باید برای جایگزینی دقیق ارائه شود.

این نسخه، همه معیارهای پرامپت بلند را کامل نمی‌کند. فرم‌های پایه ماژول‌ها عملیاتی‌اند؛ موتور ماتریس زمانی BIA و وزن‌دهی قابل تنظیم، MBCO ساختاریافته، روابط نرمال‌شده خدمات و وابستگی‌ها، گراف وابستگی، گردش تأیید، تاریخچه ممیزی، شواهد فایل‌دار، پروفایل‌های هم‌زمان چندسازمانی، رمزنگاری پشتیبان، گزارش‌های تخصصی هر استاندارد، رابط انگلیسی و تاریخچه مقایسه‌ای هنوز پیاده نشده‌اند. گزارش Word شامل جدول فارسی است؛ PDF از چاپ مرورگر است و خروجی مستقیم PDF نیست. داده نمونه ارزیابی، مدرک انطباق محسوب نمی‌شود.
