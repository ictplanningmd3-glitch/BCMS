# DBR — سامانه تداوم کسب‌وکار

نسخه ۰.۲.۰: رابط فارسی RTL با فونت یکان محلی، رنگ‌های سرمه‌ای، آبی و فیروزه‌ای، شروع خالی و مسیر «BIA ← دامنه ← پترن ← فعالیت».

## اجرای مستقیم روی ویندوز

۱. ZIP را با Extract All کاملاً استخراج کنید.
۲. فایل **index.html در ریشه پوشه DBR-Website** را با Edge یا Chrome باز کنید.
۳. نصب Node.js، سرور یا اینترنت برای نسخه مستقل لازم نیست.

`DBR-Standalone.html` نیز همین برنامه کامل تک‌فایلی است. فونت، کاتالوگ و ابزار Word و Excel درون آن تعبیه شده‌اند. پوشه `source` برای توسعه است؛ `source/index.html` با دوبارکلیک اجرا نمی‌شود. نسخه عادی `dist` برای HTTP است.

مرورگر مدیریت‌شده Codex، URLهای file:// را مسدود می‌کند. آزمون خودکار از محتوای دقیق HTML استخراج‌شده روی مسیر محلی مجاز، با شبکه قطع استفاده می‌کند. آزمون مستقیم file:// در این محیط انجام نشده است.

## شروع کاملاً خالی

هیچ نام سازمان، شخص، اقدام، BIA یا امتیاز نمونه‌ای وجود ندارد. تمام ۱۲ دامنه و ۴۰ پترن مرجع قابل مشاهده‌اند ولی در آغاز غیرفعال هستند. کاتالوگ مرجع، داده عملیاتی سازمان نیست.

در اولین بارگذاری نسخه ۲، فضای کاری نسخه ۱ به درخواست کاربر خالی می‌شود. برای جلوگیری از حذف برگشت‌ناپذیر اطلاعات پیشین، یک کپی بازیابی داخل IndexedDB با کلید `before-v2-clean-start` نگهداری می‌شود؛ این کپی در رابط، گزارش یا پشتیبان فعال وارد نمی‌شود. پاک‌کردن کل داده مرورگر، آن کپی را نیز حذف می‌کند. پایگاه داده همچنان `dbr-continuity` با جدول `state` و رکورد فعال `main` است.

## مسیر کاری

- در «سازمان و تنظیمات»، نام سازمان را در صورت نیاز وارد کنید.
- در «تحلیل اثر کسب‌وکار»، دامنه‌های قابل اجرای سازمان را فعال کنید.
- داخل هر دامنه، پترن‌های مرتبط را جداگانه فعال کنید؛ فعال‌کردن دامنه به‌تنهایی پترن‌ها را فعال نمی‌کند.
- پترن اختصاصی را با شرح و نیازسنجی به هر دامنه اضافه کنید. شناسه آن مستقل از کاتالوگ مرجع است.
- داخل پترن، توضیح مرجع، راهنمای نیازسنجی، پترن‌های مرتبط، مسئول، نیازسنجی سازمان و دوره بازنگری در دسترس است.
- هر فعالیت و BIA داخل همان پترن ساخته می‌شود؛ رکورد بدون ارتباط معتبر دامنه/پترن پذیرفته نمی‌شود.
- برای BIA، خدمت، منابع، وابستگی‌ها، دسته‌های پیامد، وزن‌ها، شدت اثر در طول زمان، آستانه، اهداف بازیابی و تأییدکننده را ثبت کنید.
- در هر پترن یا فعالیت، بازه روزانه و تاریخ مبنا را برای بازنگری، مانور، تست یا آزمون مشخص کنید.
- صفحه اول و بخش موعدها، موارد گذشته، امروز و آینده را با تعداد روز باقی‌مانده نشان می‌دهند. «ثبت انجام امروز» تاریخ مبنا را به امروز تغییر و موعد بعدی را محاسبه می‌کند؛ وضعیت فعالیت را خودکار تغییر نمی‌دهد.

## پنج سطح وضعیت و امتیازدهی

۱. هیچ اقدامی نشده — ۰٪
۲. برنامه ریزی شده — ۲۵٪
۳. در حال اجرا — ۵۰٪
۴. اجرایی شده — ۷۵٪
۵. اثربخشی تایید شده — ۱۰۰٪

پیشرفت پترن = میانگین فعالیت‌های آن. پترن فعال بدون فعالیت، صفر است. پیشرفت دامنه = میانگین پترن‌های فعال آن. پیشرفت کل = میانگین دامنه‌های فعال. دامنه فعال بدون پترن فعال، صفر است. این شاخص استقرار محصول است و گواهی ISO یا بلوغ رسمی محسوب نمی‌شود.

هشدار رادار: کمتر از ۲۵ قرمز، ۲۵ تا کمتر از ۵۰ نارنجی، ۵۰ تا کمتر از ۷۵ زرد، ۷۵ تا ۱۰۰ سبز. دامنه غیرفعال خاکستری است. رادار همیشه ۱۲ محور مرجع دارد؛ محور غیرفعال فاقد امتیاز عملیاتی است. حرکت رادار در تنظیم reduced-motion سیستم غیرفعال می‌شود.

دامنه/پترن غیرفعال، از همه شاخص‌ها، فعالیت‌های عملیاتی، BIAهای گزارشی و تقویم حذف می‌شود ولی اطلاعاتش حفظ می‌شود. فهرست خارج از شمول جداگانه در رابط و گزارش‌ها مشخص است. با فعال‌سازی مجدد، داده‌ها برمی‌گردند. پشتیبان JSON شامل داده‌های فعال و غیرفعال است.

## محاسبه BIA و موعدها

اثر هر بازه = مجموع (وزن دسته × شدت دسته) ÷ مجموع وزن‌ها. شدت ۰ تا ۵، وزن نامنفی و حداقل یک وزن مثبت است. بازه‌های زمانی قابل افزودن و حذف‌اند و ساعت تکراری پذیرفته نمی‌شود. نمودار، بازه‌ها را به ترتیب زمان ترسیم می‌کند.

اولین عبور از آستانه، تنها پیشنهاد بررسی MTPD است؛ MTPD مصوب از آستانه به‌صورت خودکار پر نمی‌شود. RTO باید کمتر از MTPD باشد. MBCO درصد ظرفیت حداقلی است. فرمول و وزن‌ها روش تصمیم‌یار سازمان‌اند، نه الزام واحد ISO.

موعد = تاریخ مبنا + تعداد روز دوره. اختلاف روزها بر اساس روز تقویمی محاسبه می‌شود؛ امروز بر مبنای Asia/Tehran است. تاریخ ورودی میلادی و نمایش تاریخ شمسی است. بازه صفر یا تاریخ خالی یعنی بدون زمان‌بندی. عبور از نیمه‌شب یا بازگشت به پنجره، موعدها را به‌روز می‌کند. سیستم در زمان بسته‌بودن مرورگر اعلان سیستم‌عامل نمی‌فرستد.

## گزارش و داده

Excel: دامنه و شمول، پترن‌های فعال، فعالیت‌ها، موعدها و ردیف‌های BIA. Word: گزارش فارسی راست‌به‌چپ از شمول و فعالیت‌های فعال. PDF با پنجره چاپ مرورگر تهیه می‌شود.

پشتیبان JSON نسخه `2.0.0` شامل دامنه‌های فعال، پترن‌های فعال/اختصاصی، تنظیمات و فعالیت‌هاست. واردکردن پس از اعتبارسنجی ساختار، تاریخ‌ها، شناسه‌های تکراری و ارتباط‌ها انجام می‌شود. جایگزینی تأیید می‌خواهد. ادغام، شناسه‌های موجود و انتخاب شمول فعلی را حفظ می‌کند. پشتیبان نسخه ۱ قابل ورود به مدل جدید نیست. پشتیبان رمزنگاری نشده است.

ذخیره در IndexedDB وابسته به مرورگر، پروفایل و origin/محل فایل است. پیش از انتقال فایل یا تغییر مرورگر پشتیبان بگیرید. نسخه مستقل به backend، حساب کاربری یا API نیاز ندارد. همگام‌سازی چندکاربره و احراز هویت سازمانی ندارد.

## توسعه و آزمون

Node.js 24 و npm:

```bash
cd /workspace/BCMS
npm ci --cache /workspace/.npm
npm run dev -- --port 5173
npm run build
npm run package
npm test
npx playwright test
```

ساخت، نسخه HTTP و HTML مستقل را تولید می‌کند. بسته‌بندی، HTML مستقل را در ریشه ZIP و کد توسعه را در source می‌گذارد. آزمون Playwright از Chromium موجود `/usr/bin/chromium` استفاده می‌کند. محیط فعلی ایزوله است؛ مگر با درخواست صریح، worktree جدید نسازید.

## مرجع و محدودیت‌ها

۱۲ دامنه و ۴۰ پترن نامزد از اطلس ارسالی نسخه ۰.۳.۲ گرفته شده‌اند؛ نام‌ها و ارتباط‌های اصلی حفظ شده‌اند. کاتالوگ تحویلی به تعریف، نیازسنجی و روابط مورد نیاز محدود شده و نام خبرگان/اطلاعات داوری به رابط وارد نمی‌شود. متن کامل استانداردهای ISO و مدل ۱۶ دامنه‌ای ارائه نشده‌اند. هیچ گواهی یا بند استانداردی اختراع نمی‌شود.

فونت Yekan از typeface-yekan@1.0.11، دارای مجوز OFL در assets است. نشان هندسی از روی تصویر ارسالی بازطراحی شده و فایل اصلی لوگو در دسترس نبود.

سایر نیازهای بلندمدت پرامپت اولیه مانند گراف وابستگی نرمال‌شده، گردش تأیید چندنفره، فایل‌های شواهد، گزارش تخصصی هر بند ISO و همگام‌سازی چندسازمانی هنوز پیاده‌سازی نشده‌اند.
